# 用自己的書法網站學 Codex

不必先背會整套程式語法。先學會：提出明確修改 → 看懂改了哪些檔案 → 預覽 → 保存版本。

## 先分清楚四件事

| 工具／動作 | 在這個專案做什麼 |
| --- | --- |
| ChatGPT 對話 | 討論策展、內容、設計需求 |
| VS Code 裡的 Codex | 讀取已開啟的專案、修改實際檔案、協助檢查 |
| Git／GitHub | Git 保存可回復版本；GitHub 保存遠端程式碼 |
| GitHub Pages | 把程式碼部署成可公開瀏覽的網站 |

## 第一課：在 Mac 開啟專案

1. 解壓縮完整專案，用 VS Code 開啟最外層資料夾。
2. 在擴充功能搜尋 Codex，確認發行者為 OpenAI，安裝並依畫面登入。
3. 點 Codex 圖示開啟側欄；若找不到，可在命令選擇區搜尋 Codex: Open Codex Sidebar。
4. 先建立 Git 初版紀錄，詳見 GITHUB.md。
5. 把下面這段交給 Codex：

> 請先閱讀 AGENTS.md、README.md 與 docs/MAINTENANCE.md。用初學者能懂的繁體中文，告訴我首頁、作品資料、CSS 和 JavaScript 分別在哪裡。先解釋，不修改檔案。

這份 AGENTS.md 已記下你核可的策展與維護原則。它能為專案提供指引；每次仍需把當次需求講清楚。不同對話不一定有先前聊天的全部內容，重要決定應保留在專案文件中。

## 第二課：做一次小修改

先開啟 Live Server，看目前畫面。挑一個簡單的文字或字級調整，不同時重做整頁。例如：

> 請把「關於我」區塊的內文略為放大，提高閱讀性，保持目前布局、姓名與印章不變。請延續 base.css 的共用字級原則，避免重複樣式。修改後告訴我實際調整了哪個檔案和數值，並執行適合的檢查。這次只做本機修改，不 push、不部署。

在 VS Code「原始檔控制」點檔案，可以看修改前後的差異（diff）。如果改了不相干的作品內容，請 Codex 說明並修正。瀏覽器重新整理，親自看字級與窄畫面。

確認滿意後，再用下面這段：

> 請摘要這次修改，確認檢查結果，只把這次相關修改建立一個 commit；先不要 push。

## 第三課：更新一件作品

> 請只更新 dist/data/artworks.json 裡 id 為「指定代號」的作品，把年份改為「已確認年份」。其他欄位、圖片、落款與排版保持原樣。請檢查 JSON 與作品頁，完成後告訴我修改差異。若備存資料與公開展籤有不同欄位，請說明兩者顯示關係。

先把指定代號與年份替換成實際資料。落款不清楚時提供原圖，不能讓 Codex 為了填滿資料而推測。

## 第四課：從本機到 GitHub

照 GITHUB.md 建立自己的 repository。每次請 Codex 做的事可依需要分開說清楚：

- 「儲存檔案」：只是本機檔案改好了。
- 「建立 commit」：在 Git 留下一個可回復版本。
- 「push 到我的 repository」：把 commit 傳到 GitHub。
- 「部署 Pages」：讓公開網站更新；啟用自動工作流程後，push main 就會觸發。

工作流程是 **提出一個明確需求 → 修改 → 預覽與檢查 → 看差異 → commit → push／部署**。把 Git 想成可回看的版本紀錄即可，不必一次學完所有指令。

## 如何描述需求

提供四項資訊最有幫助：位置、希望怎麼變、必須保留什麼、怎麼算完成。例如：

> 位置：花氣帖影片頁。希望：播放結束只在中央顯示三角重播鍵。保留：原影片與配樂。完成條件：重播時從頭開始，手機也能點，沒有額外控制列。

遇到錯誤，提供網址／本機頁面、操作順序、預期結果、實際結果與截圖；不只說「壞了」。若尚不確定解法，可先請 Codex 說明相關檔案和可能原因。
